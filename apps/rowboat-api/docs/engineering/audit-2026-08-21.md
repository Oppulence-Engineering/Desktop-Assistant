# Code quality audit baseline — 2026-08-21

## Scope and architecture

The audit covered 425 handwritten/generated Go files under `internal`, 179
package-local test files, 72 Ent schemas, server/worker/scheduler/projector/
migration/dev entrypoints, route wiring and middleware, auth context and policy,
Ent interceptors/hooks, migrations and generation, Temporal workflows and
activities, outbound clients, configuration, Makefile, repository Lefthook,
and API CI workflows.

The architecture is intentionally a schema-driven modular monolith with
vertical feature packages, manual DI, direct Ent persistence, persistence-layer
tenancy, explicit state machines, immutable audit facts, idempotent distributed
operations, and Temporal orchestration. That philosophy is retained.

## Findings and actions

### Security registry drift was manually enforced

- **Severity:** High
- **Location:** `ent/schema`, `internal/db/interceptors.go`, `internal/db/hooks.go`
- **Why it matters:** A tenant schema added to only one registry could permit an unscoped read or write path.
- **Existing behavior:** All current user-owned schemas were correctly registered, but future completeness depended on review.
- **Recommended behavior:** Derive expected tenant ownership from handwritten schemas and fail on missing read/write registration.
- **Action taken:** Added `internal/qualityguard` and fixture/repository tests; wired it to `make architecture`, hooks, and CI.

### Route authorization is explicit but centralized and manual

- **Severity:** High
- **Location:** `cmd/server/wire.go`, feature `Mount` methods
- **Why it matters:** A new route can be placed outside the intended JWT/provider/internal middleware group.
- **Existing behavior:** Routes are grouped and well-commented; focused exposure tests exist, but no complete declarative route model exists.
- **Recommended behavior:** Require an explicit security class and denial tests for every endpoint; consider a router security inventory only when it can be derived without duplicating wiring.
- **Action taken:** Codified fail-closed route rules and required tests. A brittle source parser/declarative router rewrite was deliberately not added.

### Quality commands were incomplete and test/race tiers conflated

- **Severity:** Medium
- **Location:** `Makefile`
- **Why it matters:** Agents lacked one normal completion gate; full race cost encouraged bypassing the only test target.
- **Existing behavior:** `make test` always used `-race`; lint and format existed; security/generation ran mostly in CI.
- **Recommended behavior:** Separate fast and expensive tiers with one canonical agent command.
- **Action taken:** Added `fmt-check`, `architecture`, `mod-verify`, `test-race`, `security`, `verify`, `verify-ci`, pinned tools, and install target.

### Static analysis omitted important defect classes

- **Severity:** Medium
- **Location:** `.golangci.yml`
- **Why it matters:** Context loss, unsafe error semantics, SQL cleanup, request context omissions, and common security mistakes were not all checked.
- **Existing behavior:** Standard linters plus bodyclose/gocritic/misspell/revive.
- **Recommended behavior:** Add only high-signal linters with explicit purpose and a clean baseline.
- **Action taken:** Added contextcheck, errorlint, gosec, nilerr, noctx, rowserrcheck, sqlclosecheck, unconvert, and goimports formatting.

### Temporal correctness relied primarily on discipline/tests

- **Severity:** Medium
- **Location:** `internal/agentworkflow`, `internal/backgroundtaskworkflow`
- **Why it matters:** A direct clock/random/network call in workflow code can break replay.
- **Existing behavior:** Current workflow code documents determinism and uses Temporal APIs; activities perform side effects.
- **Recommended behavior:** Retain SDK tests and catch obvious forbidden calls early.
- **Action taken:** Integrated the typed `rbtemporal` analyzer scoped to functions accepting `workflow.Context`; documented its intentional limits.

### Generated-code workflow was strong but local guidance fragmented

- **Severity:** Medium
- **Location:** Makefile generation targets, CI, agent docs
- **Why it matters:** Manual generated edits or partial regeneration break contracts across Ent/OpenAPI/GraphQL/protobuf/SDK.
- **Existing behavior:** Ordered generators and CI drift checking already existed; root hooks regenerated common schema paths.
- **Recommended behavior:** Make source-to-artifact ownership explicit and keep CI authoritative.
- **Action taken:** Documented generated ownership and added `generate-check`; preserved the established pipeline.

### Configuration and composition roots are concentration points

- **Severity:** Medium
- **Location:** `internal/appconfig/config.go`, `cmd/server/wire.go`
- **Why it matters:** Cross-domain growth makes validation and security review harder; setter wiring can permit partial objects.
- **Existing behavior:** Typed centralized config and transparent manual DI, with several constructor-plus-setter patterns.
- **Recommended behavior:** New required dependencies use constructors/validated options; split only along cohesive domain boundaries.
- **Action taken:** Established forward rules; no risky wholesale refactor was performed.

### Shared outbound policy had limited direct package coverage

- **Severity:** Medium
- **Location:** `internal/outbound`
- **Why it matters:** Retry, breaker, concurrency, and body-bound behavior is a cross-provider safety boundary.
- **Existing behavior:** The implementation centralizes these controls; many consumers test surrounding behavior.
- **Recommended behavior:** Add focused transport tests for retry idempotency, cancellation, bounds, and breaker transitions.
- **Action taken:** Recorded as a high-priority follow-up to avoid mixing a behavioral transport rewrite into standards enforcement.

### Migration ownership combines auto-migration and checked-in SQL

- **Severity:** Medium
- **Location:** `internal/db/db.go`, `cmd/migrate`, `migrations/`
- **Why it matters:** A schema may work in local SQLite while being unsafe or operationally incomplete in Postgres.
- **Existing behavior:** Auto-migrate supports local/test environments and SQL files are checked in.
- **Recommended behavior:** Treat SQL plus rollout/backfill/recovery planning as the production path.
- **Action taken:** Formalized migration standards; generation drift remains enforced in CI.

## Remaining priorities

No blocking architectural defect was found in the audited baseline. High
priority follow-ups are focused outbound transport tests, a non-duplicative
route-security inventory/test harness, incremental config/wiring decomposition,
and a production migration validation strategy against Postgres/Atlas. Optional
improvements include targeted package coverage reporting and scheduled longer
integration/replay suites.
